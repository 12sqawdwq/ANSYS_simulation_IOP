# 文档治理与实验记录规范

## 1. 目标

仓库文档必须同时满足：

- 新接手者能快速找到当前结论和运行入口；
- 探索阶段的假设、失败、预期和中间数据不丢失；
- 结论变化可通过 Git、时间和产物哈希追溯；
- 不依靠 `v1/v2/final/latest` 文件副本管理版本；
- 合并文档时不伪造、蒸馏或删除重要实验描述。

## 2. 每个大型实验的五类文档

### 2.1 主要结论文档

建议文件名：`docs/MAIN_CONCLUSIONS.md`。

必须包含：

- 当前冻结结论；
- 数值证据和适用范围；
- 允许/禁止的解释；
- 已被证伪的路径；
- 下一步独立验证条件。

它不是宣传摘要，不能删除负结果和限制条件。

### 2.2 系统工程配置文档

建议文件名：`docs/SYSTEM_ENGINEERING.md`。

必须包含：

- 软件、主机和可执行文件；
- 几何、材料、边界和加载路径；
- 当前配置文件；
- 正式命令、目录、存储和 QC；
- 数据溯源及大文件位置。

### 2.3 脚本索引文档

模块使用 `docs/SCRIPT_INDEX.md`，仓库全局使用 `docs/SCRIPT_INDEX.md`。

每个当前脚本记录职责、输入、输出和状态；退役入口记录替代关系及 Git 恢复点。

### 2.4 系统日志与更改日志

模块使用 `docs/CHANGELOG.md`，仓库全局使用 `docs/CHANGELOG.md`。

至少保存：

- 时间；
- Git commit；
- 修改文件；
- 提交主题或变更内容；
- 正式运行另保存主机、配置、输入哈希、外部数据路径和运行状态。

Git diff 是完整变更真源；文档是可读索引，不能用文档版本号取代提交号。

### 2.5 中间结论文档

放在 `docs/intermediate/`，按物理问题命名。

必须预注册问题、假设、输入、预期结果、证伪条件、验收门限和停止条件；每轮追加 Git SHA、配置、结果和与预期的差异。路径结论确定后：

1. 把完整最终结论和限制同步到主要结论文档；
2. 中间文档标记 `concluded` 或 `abandoned_with_evidence`；
3. 保留探索过程，不删除失败路径；
4. 不改名为 `final`。

## 3. 大实验合并规则

当多个阶段文档属于同一大型实验且根目录已经难以导航时，可合并为 `docs/EXPERIMENT_RECORD.md`。合并必须：

1. 逐份保留原文叙述、公式、表格、数值和限制；
2. 只允许换行/BOM规范化和相对链接重定向等机械变化；
3. 保存每个原文件的原路径、SHA-256、Git blob 和行数；
4. 对每个合并段落保存哈希并建立测试；
5. 在删除原工作树文件前完成完整性验证；
6. 明确可恢复的父提交；
7. 主要结论另行维护，不能要求读者从十万字记录中猜测当前结论。

高眼压模块的实现可作为范例：

- `high_iop_mechanical_transfer_t1p25_c0p60/docs/EXPERIMENT_RECORD.md`
- `high_iop_mechanical_transfer_t1p25_c0p60/docs/SOURCE_DOCUMENT_MANIFEST.json`
- `tests/test_high_iop_document_archive.py`

## 4. 文件命名与 Git

禁止用以下状态词制造并行脚本/文档副本：

```text
v1, v2, final, final2, latest, new, old, backup, copy
```

允许出现在有物理意义或实验范围意义的名称中：

- 压力范围：`calibration_0_to_50`；
- 推进量：`0p26_0p28`；
- 日期化不可变结果：`20260731_*`；
- ANSYS 产品版本或环境路径：`v252`。

修改当前实现时直接提交 Git；高风险清理使用新分支，测试通过后合并。需要复现实验旧状态时 checkout 对应 commit/tag，而不是保留旧脚本副本。

## 5. 删除判据

可从当前工作树删除：

- 已被更完整当前入口替代的阶段性启动器/规格；
- 与当前脚本内容完全重复的副本；
- 浏览器下载重复文件；
- 可由脚本重建且已有权威产物的临时文件。

不得仅因“看起来旧”删除：

- 原始结果和 QC；
- 负结果、证伪记录和限制；
- 不同物理问题的脚本；
- 数据来源与校验清单；
- 尚未确认意图的用户工作树修改。

删除前必须执行依赖搜索、记录替代关系并运行测试。

## 6. 全局实验基线治理

全局模型基线使用根目录 `config/model_baseline.json` 作为机器可读真源；当前统一眼睑厚度为 1.25 mm。新普通实验不得在局部脚本中另设未说明的默认厚度。

研究厚度效应、厚度边界或厚端网格误差时可以显式偏离，但配置和结果元数据必须同时保存全局参考值、端点实际厚度和覆盖原因。基线调整只影响新运行的默认值；历史输入、结果和文档中的实际厚度不得追溯改写。完整语义见 [`GLOBAL_BASELINE.md`](GLOBAL_BASELINE.md)。
